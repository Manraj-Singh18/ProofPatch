Local verification
Proof before trust

Let AI write the patch. Let evidence decide if it is true.

ProofPatch gives a coding agent permission to propose changes, but not permission to declare success. The computer checks what actually changed, protects the tests, runs the tests independently, and only then accepts or rejects the result.

◈

The model is not the authority

Everything the AI says is treated as a proposal. Proof comes from observed files, protected test state, test execution, and a cryptographic commitment to the evidence.

Start a verification run

Describe the change in normal language. ProofPatch will ask the local coding agent to implement it.

What ProofPatch checks

Four simple questions explain the entire proof.

01 · PROPOSE
What did the AI ask to change?The model's response is captured exactly. It is evidence about what the AI proposed, not proof that the proposal is correct.
02 · OBSERVE
What actually changed?ProofPatch hashes the repository before and after the edit so the recorded patch can be compared with the real filesystem.
03 · PROTECT
Did the AI leave the tests alone?Protected test files are checked before and after the patch. Changing a test to make a failure disappear is not accepted.
04 · VERIFY
Does the code actually work?The test command runs independently against the resulting repository. A green test run is the evidence that determines acceptance.
A successful AI answer is not proof. A verified repository state is.

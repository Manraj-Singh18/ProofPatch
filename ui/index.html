Local verification
Proof before trust

Let AI write the patch. Let evidence decide if it is true.

PatchProof treats the model's answer as a proposal. It independently observes the repository, protects the tests, runs the tests, and records a cryptographic commitment. An optional Ethereum anchor makes that commitment publicly timestampable and independently verifiable.

Start a verification run

Describe the change in normal language. PatchProof will ask the local coding agent to implement it.

The local model may take a little while.

How the proof works

Four questions make the result understandable.

01 · PROPOSE
What did the AI request?We record the model's proposed edit. A proposal is not proof.
02 · OBSERVE
What actually changed?File hashes and patch evidence are compared with the real repository state.
03 · PROTECT
Were tests left alone?Protected test and toolchain paths cannot be changed by the agent.
04 · VERIFY
Does it actually work?The test command runs independently. Its result determines acceptance.
A successful AI answer is not proof. A verified repository state is.
